一、启动与登录态判定

数据源：

● 登录凭证：小程序启动时静默获取的临时凭证，由服务端换取用户身份标识（无界面、无弹窗）
● 登录态：本地缓存的会话凭证 + 服务端校验结果
● 绑定关系：按身份标识读取「供应商绑定关系」数据

显示逻辑：

● 判定阶段不展示任何界面，用户全程无感知
○ 已绑定且登录态有效 → 跳过登录页，直接进入首页
○ 未绑定 或 登录态失效 → 展示登录页
○ 判定未返回前展示启动占位（骨架屏 / 品牌页），不得出现白屏
■ 超过 3 秒未返回 → 底部轻提示 【网络较慢，正在重试】，3 秒后自动重试一次
■ 重试仍失败 → 【网络异常，请检查网络后重试】，提供【重新加载】按钮

交互逻辑：

● 前置条件：无。用户打开小程序即触发，不依赖任何用户主动操作
● 判定不阻断首屏：判定期间登录页可正常展示，用户可先阅读页面内容
● 同一会话内只判定一次，页面切换不重复请求

状态机：

● 状态集合：未判定 / 已登录 / 未登录
○ 未判定 → 已登录：命中有效绑定关系
○ 未判定 → 未登录：无有效绑定关系
○ 已登录 → 未登录：用户主动退出登录（「我的」页触发）或登录态过期
○ 未登录 → 已登录：功能块三 / 功能块四 登录成功

补充注意事项：

● 微信授权仅能提供身份标识，不提供手机号；本系统以手机号定位供应商账号，因此首次进入需走功能块三完成账号定位
● 判定失败不阻断浏览，仅在用户发起需身份的操作时再次引导登录
● 本块的身份识别结论（已绑定 / 待确认 / 未绑定）与身份绑定 PRD 功能块 5.1 为同一套逻辑，不重复实现

二、登录页（页面框架）

数据源：

● 页面为静态框架，不请求业务数据
○ 仅底部版本号读取全局配置（当前【v2.2.42.2】），版本号随发版自动更新，不硬编码

显示逻辑：

● 页面自上而下依次为：导航区（左上返回箭头 + 居中标题【登录】）、品牌区（品牌 logo + 名称【喜乐点餐商家】居中）、主按钮【手机号快捷登录】（蓝色渐变、圆角胶囊、白字）、次按钮【账号密码登录】（浅灰底、深色字）、文字链【没账号去注册】（蓝色、右对齐）、协议行（空心圆复选框 + 【勾选即代表同意《隐私政策》】，协议名蓝色可点）、底部固定灰字说明与版本号
○ 复选框默认不勾选，每次进入登录页重置为未勾选
○ 底部说明固定文案：【喜乐点餐商家端小程序为喜乐点餐供应商内部工具，仅限我司合作供应商进行登录。】置灰展示
■ 品牌区、按钮文案均为固定内容，无空值兜底场景

交互逻辑：

● 点击返回箭头：返回上一页；无上一页时退出小程序
● 点击《隐私政策》：新开协议页（H5 web-view 或内置页面），不影响登录页状态
● 点击【手机号快捷登录】：进入功能块三
● 点击【账号密码登录】：进入功能块四
● 点击【没账号去注册】：进入功能块五

补充注意事项：

● 手机号授权仅允许由用户点击主按钮触发，禁止进入小程序自动调起（平台新规硬性要求）
● 本页不提供「微信一键登录」入口：微信授权仅能获取身份标识，无法获取手机号；本系统以手机号定位供应商账号，微信一键登录无业务价值

三、手机号快捷登录（主路径）

数据源：

● 手机号：微信原生手机号授权面板返回（用户最终选定的手机号）
○ 面板可展示多个手机号（v1.4）：微信用户在「微信 > 发现 > 小程序 > 个人中心」添加过多个手机号时，授权面板会全部列出，最近提供过的带「上次提供」标记，底部有「管理号码」入口（跳转上述个人中心，可添加手机号）。面板的号码列表、排序与样式均由微信客户端渲染，开发者无法控制内容，只接收用户最终选定的号码
● 供应商账号：服务端按手机号匹配供应商账号列表
● 微信标识：启动阶段静默获取的身份标识（规则见功能块一），无界面

显示逻辑：

● 登录成功 → 进入该手机号对应供应商账号的主页
○ 该手机号命中多个供应商账号 → 进入账号选择页，列表展示全部账号（供应商账号名称 + 账号状态），选中后进入对应账号
○ 该手机号未命中任何账号 → 提示【该手机号没有注册供应商账号】，停留登录页（v1.4 定稿文案，替换原「未开通供应商账号，请联系对接商务」）
○ 账号被停用 / 审核中 → 红字【账号暂不可用：具体原因】

交互逻辑：

● 点击【手机号快捷登录】前置校验：
○ 未勾选协议 → 拦截，红字【请先阅读并同意《隐私政策》】，不调起授权面板
○ 已勾选 → 调起微信原生手机号授权面板
■ 用户点【允许】→ 拿到手机号 → 服务端执行匹配（见显示逻辑三分支）
■ 用户点【不允许】→ 面板关闭，停留登录页，不弹错误提示（用户主动拒绝不算异常）
● 登录成功：服务端建立绑定关系（身份标识 ↔ 供应商账号 ↔ 手机号），写登录日志（账号 + 时间）
● 已绑定用户再次进入小程序：由功能块一按绑定关系静默登录直接进主页，不再弹授权面板、不停留登录页

状态机：

● 全部业务状态：未登录 → 授权中 → 登录成功 / 登录失败
○ 未登录 → 授权中：点击主按钮且协议已勾选
○ 授权中 → 未登录：用户点【不允许】或关闭面板（可重新触发，无次数限制）
○ 授权中 → 登录成功：手机号命中有效账号
○ 授权中 → 登录失败：网络异常或服务端错误，红字【登录失败，请重试】，回未登录态可重试
■ 登录成功为终态，本次会话不可回退；退出登录由「我的」页入口触发，回未登录态

补充注意事项：

● 一个微信可绑定多个供应商账号：绑定关系按「微信 × 账号」多条存储，各账号的微信昵称等资料独立存储，切换账号后昵称随之切换
● 用户微信换绑手机号：不影响已建立的绑定关系（主键为身份标识），手机号仅作首次定位与联系方式
● 非供应商微信误入本端：未命中任何账号 → 走注册申请流程（功能块五），不暴露任何供应商数据

四、账号密码登录（辅助路径）

数据源：

● 账号、密码：用户手动输入；服务端校验
● 微信标识：启动阶段静默获取的身份标识（无界面、无弹窗），仅用于登录成功后建立绑定关系

显示逻辑：

● 页面元素：账号输入框（占位【请输入手机号】）、密码输入框（占位【请输入密码】，密文展示 + 可见性切换图标）、主按钮【登录】、文字链【忘记密码】
○ 账号或密码为空时主按钮置灰，不可点击

交互逻辑：

● 点击【登录】：
○ 校验通过 → 登录成功，流转同功能块三（含多账号选择）
○ 账号或密码错误 → 红字【账号或密码错误】，不区分具体是哪项错误
○ 连续错误达 5 次 → 锁定 15 分钟，红字【错误次数过多，请 15 分钟后重试】，期间登录按钮置灰并显示剩余时间
● 点击【忘记密码】：进入手机号验证码重置流程

补充注意事项：

● 本路径不调起微信手机号授权面板：账号身份由账号密码确定，手机号读取账号档案中的注册手机号；微信手机号授权仅服务于「手机号快捷登录」路径
● 登录成功后静默绑定身份标识 ↔ 供应商账号（无弹窗）：此后该微信再次进入小程序可按绑定关系静默登录，无需重复输密码
● 该路径服务于多店铺商户等需要独立账号体系的场景，与手机号快捷登录进入同一套供应商账号，两者登录后数据完全一致
● 本路径进入的账号，其微信昵称槽位默认为空（用户从未填写过），进入「我的」页时按功能块七展示引导条，需用户手动完善 —— 不自动获取、不弹微信授权

五、注册入口（没账号去注册）

数据源：

● 注册信息：用户手动输入；账号开通结果：后台审核

显示逻辑：

● 跳转注册页；提交后页面提示【注册申请已提交，等待审核】，审核结果通过短信 / 群通知告知

交互逻辑：

● 提交注册 → 生成待审核账号，状态为【审核中】，此状态下登录按功能块三「账号暂不可用」处理

补充注意事项：

● 本端为内部工具，注册不等于开通：需运营审核通过后才可登录。注册页是否采用邀请制（仅商务开通链接可注册）待确认，见文末待确认事项

六、隐私与协议

数据源：

● 协议文本：法务提供，H5 页面承载

显示逻辑：

● 复选框默认不勾选；《隐私政策》为蓝色可点文字

交互逻辑：

● 点击复选框：勾选 / 取消勾选，实时切换
● 未勾选时点击任一登录按钮：拦截并提示（文案见功能块三），不静默失败

补充注意事项：

● 微信后台《用户隐私保护指引》须同步声明以下字段，声明项须与实际采集一一对应，未声明的采集在真机被直接拦截（运行时报错、无界面提示）：
○ 手机号 —— 用于账号定位与订单通知（否则手机号授权面板无法调起）
○ 昵称 —— 用于售后群内核对对接人（否则「使用微信昵称」能力失效）
● 声明用途不得超出实际使用范围（例如声明「仅用于订单通知」，即不得用于营销触达）

七、登录后的微信昵称引导

数据源：

● 微信昵称：用户主动填写（`input type="nickname"`），微信不提供任何自动获取接口
● 存储维度：昵称按「绑定关系」存（微信 × 供应商账号），各账号独立；采集规则与校验细则见身份绑定 PRD 功能块 5.5

显示逻辑：

● 登录成功进入主页后，若当前账号的微信昵称为空 → 页面顶部展示无遮罩引导条：【完善微信昵称，在售后时可以根据昵称@到你】 + 【去设置】+ 最右【×】，可关闭（v1.5 定稿文案）
○ 昵称已设置 → 不展示引导条
○ 昵称未设置且未处理时，「我的」页昵称位展示引导态（规则见身份绑定 PRD 功能块 5.4），禁止展示空白或 undefined
○ 引导条出现时机为落地页渲染完成后，不阻塞首屏操作

交互逻辑：

● 点击引导条【去设置】→ 展开填写层（昵称输入框 + 「使用微信昵称」辅助入口）
○ 保存空值 → 拦截，红字【请输入微信昵称】
○ 保存成功 → 【保存成功】，写变更日志（旧值 / 新值 / 时间，仅后台可查，C 端不展示入口），引导条消失
○ 点击关闭或「稍后再说」→ 本次会话不再弹，入口保留在「我的」页昵称行 ✎

补充注意事项：

● 引导条文案以 v1.5 定稿为准（见显示逻辑首条），只承载这一句提醒；「为什么要与售后群昵称保持一致」的解释由填写层承担，引导条不得承载多句说明
● 登录成功后不叠加自定义弹层：手机号登录已消耗一次微信原生面板，再弹层即 5 秒两弹窗，流失率高
● 昵称输入框必须为可编辑的 `input type="nickname"`，禁止设置 readonly / disabled；「使用微信昵称」工具条由微信真机渲染，仅在真机出现（基础库 2.21.2+），开发者工具与模拟器不可见
