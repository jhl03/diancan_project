一、需求背景与目标

背景。供应商目前以微信群为主要沟通阵地，在群内以微信昵称示人，不提供企业实名。当发生售后争议时，客服从客户口述的微信昵称出发，无法在系统内定位到对应的供应商档案，只能人工在群成员里翻找、逐张订单比对，定位一次平均耗时较长，且存在匹配到错误供应商的风险。

目标。建立「供应商微信身份 ↔ 系统供应商档案」的稳定绑定关系，使客服拿到任意一条微信侧线索（昵称、群昵称、订单）即可反查到唯一的供应商档案。

核心设计原则。让供应商只做「点一下」这一个动作，不要求其填写任何实名信息；绑定关系以平台级稳定标识为主键，昵称仅作为缩小候选范围与人工核对的辅助线索。

适用范围：本需求成立于企业微信客户群场景（已确认）——企微侧可获取外部客户标识与群昵称。普通微信群不向第三方开放成员列表与昵称，若存在使用普通微信群的供应商，需另行走「运营后台人工关联」流程，不在本 PRD 范围内。
与登录环节的衔接：用户打开小程序后，先执行登录态判定（已绑定则静默放行，未绑定则展示登录页完成账号定位），再执行本文档 5.1 的身份识别。登录页形态、手机号账号定位规则见《PRD_供应商端登录_2026-09-22》。注意：进入首页后的自动弹层存在两处来源——本文档 5.2 的身份确认弹层与登录 PRD 的昵称引导条，二者不得同时弹出，优先级待确认（见登录 PRD 功能块七）。

二、术语定义

术语定义本文档中的角色
统一身份标识同一微信用户在同一开放平台主体下的全局唯一标识绑定的首选主键
小程序身份标识同一微信用户在同一小程序内的唯一标识降级主键，用于历史数据兼容
企微客户标识企业微信为每个外部客户分配的唯一标识企微侧关联主键
群昵称客户在该企业微信客户群内显示的昵称仅用于缩小候选范围与人工核对，不参与自动匹配
绑定关系一条「微信身份 → 供应商档案」的映射记录核心业务数据
主身份一个供应商名下多条绑定记录中被设为默认的那一条用于多微信号场景的默认登录身份
供应商账号系统内承载业务数据（订单、报价、余额）的账号主体，其名称来自供应商档案，即「我的」页第一行展示的名称只读展示，不提供修改入口
绑定方式产生该条绑定记录的来源，枚举三类：① 标识自动匹配（身份标识命中企微客户）／② 候选匹配（群昵称模糊比对后由用户点选 + 运营确认）／③ 人工指定（客服或运营后台手动关联）审核列表与售后反查的展示字段

三、角色与使用场景

角色核心诉求主要场景
供应商不填实名也能用系统；换微信名不影响使用首次进入小程序、日常接单、查看订单
运营人员批量确认绑定关系，处理异常绑定每日审核绑定申请、修正错误绑定
客服用客户口述的昵称秒查供应商档案售后工单处理、订单归属确认

四、全局规范

4.1 空数据统一规则

  • 所有模块无数据、无记录、无内容时，统一兜底显示 【-】
  • 昵称类字段为空时，按展示位置分两类处理，不得混用
  • C 端「我的」页等可编辑位置：展示引导态，文案见 5.4（不展示【微信用户】，否则用户不知道该去设置）
  • 后台审核列表、售后反查等只读展示位置：兜底展示 【微信用户】
  • 任何位置均不得展示空白、null 或 undefined

4.2 名称匹配规则

  • 通过供应商编号匹配供应商名称，匹配不到时展示 【供应商信息异常，请联系运营】红字展示
  • 绑定关系失效时，页面身份区展示 【绑定已失效，请重新确认身份】红字展示

4.3 操作记录规则

  • 所有涉及绑定关系的操作，固定记录 操作人名称 + 操作时间，多条记录按时间倒序展示

4.4 标识安全规则

  • 统一身份标识、企微客户标识仅在服务端存储与传递
  • 任何页面、接口响应、客户端日志中不得出现完整标识；后台如需展示，统一做中段脱敏
  • 昵称属于用户个人信息，须在用户隐私保护指引中声明后方可采集；未声明即静默失效（运行时不报错、界面上无提示），联调时必须核对（详见 5.5 采集规则）

五、功能需求

功能名称　静默登录与身份识别菜单路径　小程序启动即触发 / 全站接口地址　POST /api/wx/login
数据源：
  • 登录凭证来自小程序端登录接口返回的临时凭证，由服务端换取用户身份标识
  • 绑定关系来自「供应商绑定关系」数据，按身份标识读取
  • 企微侧身份来自「企微客户镜像」与「企微客户群成员」两份同步数据
  • 供应商名称取自「供应商档案」数据，按供应商编号匹配
显示逻辑：
  • 识别过程不展示任何界面，用户全程无感知，首屏直接渲染
  • 识别结果按四类分流处理
  • 已绑定：直接进入首页，无任何弹层、提示、动效
  • 待确认：进入首页，顶部固定展示待确认横条
  • 未绑定且有候选：进入首页，自动弹出身份确认弹层
  • 未绑定且无候选：进入首页，自动弹出身份确认弹层并落至搜索态
  • 请求未返回前，首屏展示骨架屏
  • 超过 3 秒未返回，底部展示轻提示 【网络较慢，正在重试】，3 秒后自动重试一次
  • 重试仍失败，展示 【网络异常，请检查网络后重试】红字展示，提供【重新加载】按钮
交互逻辑：
  • 前置条件：完成登录态判定后触发（已绑定用户由登录环节直接放行，未绑定用户先经登录页完成账号定位，见《PRD_供应商端登录_2026-09-22》功能块一）
  • 已绑定用户不做任何打断，直接放行至首页
  • 识别失败不阻断使用，用户仍可浏览公开页面；仅在发起需身份的操作时再次引导
  • 同一会话内识别只执行一次，页面切换不重复请求
状态机：
  • 状态集合：未识别 / 已绑定 / 待确认 / 未绑定
  • 未识别 → 已绑定：识别结果命中唯一有效绑定关系
  • 未识别 → 待确认：命中一条待复核的绑定记录
  • 未识别 → 未绑定：无任何命中
  • 已绑定 → 已失效：供应商解约、账号停用
  • 已失效 → 未绑定：用户重新发起身份确认
  • 待确认 可被运营驳回，回退至 未绑定；驳回为可重复动作
补充注意事项：
  • 统一身份标识缺失时（微信账号未与开放平台主体关联）自动降级为小程序身份标识匹配，不报错、不阻断
  • 识别不可作为页面加载的阻塞条件，识别超时也必须保证首屏可用
功能名称　身份确认弹层菜单路径　首页 / 底部半屏弹层接口地址　POST /api/wx/binding/confirm
数据源：
  • 候选供应商列表由服务端根据群昵称、企微备注与供应商档案名称做模糊比对后返回，最多 3 条
  • 匹配依据优先级：供应商简称 > 供应商全称
  • 候选按匹配度由高到低排序
  • 搜索态数据来自供应商档案，按输入关键词实时检索
显示逻辑：
  • 底部半屏弹层，自下而上滑入；含标题、说明文案、候选列表、搜索入口、主按钮
  • 标题固定文案 【请确认你的供应商身份】
  • 说明文案固定文案 【仅用于售后时核对订单归属，不会展示给客户】
  • 候选列表每行展示：供应商名称 + 匹配度标识（高 / 中 / 低）
  • 无候选时，列表区展示 【未找到匹配的供应商，请搜索名称】
  • 搜索结果为空时，展示 【未搜索到该供应商，请联系运营开通】红字展示
交互逻辑：
  • 点击候选项：选中态高亮，主按钮由不可点变为可点
  • 前置校验：未选中任何候选时，主按钮置灰不可点
  • 点击【确认】后提交绑定申请，成功则关闭弹层并跳转待确认态
  • 提交成功提示 【已提交，等待运营确认】
  • 提交失败提示 【提交失败：网络异常】红字展示，弹层不关闭，允许重试
  • 点击遮罩或右上角关闭，弹层下滑收起，首页正常可用
  • 关闭后本次会话不再自动弹出，可在「我的」页手动唤起
补充注意事项：
  • 弹层不得要求用户手动输入供应商实名，只允许「点选候选」或「关键词搜索后点选」两种方式
  • 弹层不得遮挡底部核心操作区域后无限停留，必须提供关闭入口
  • 明确告知用途，不得使用「不确认将无法使用系统」等强制性措辞
功能名称　待确认状态提示菜单路径　全站顶部横条 + 我的页接口地址　GET /api/wx/binding/current
数据源：
  • 绑定记录状态来自「供应商绑定关系」数据
  • 审核进度文案由系统按状态生成
显示逻辑：
  • 待确认期间，全站顶部固定展示横条 【身份待运营确认，确认后即可接单】，不可关闭
  • 「我的」页身份区展示所选供应商名称，右侧展示状态标签 【待确认】
  • 状态标签配色与文案一一对应
  • 待确认：橙色，文案 【待确认】
  • 已绑定：绿色，文案 【已绑定】
  • 已失效：红色，文案 【已失效】红字展示
交互逻辑：
  • 待确认期间，不阻断浏览，但涉及接单、报价等业务动作时拦截，提示 【身份确认后可操作】
  • 支持手动刷新状态：点击横条右侧【刷新】重新查询
  • 刷新中按钮置灰并展示加载态，防重复点击
  • 状态变更为已绑定时，横条自动消失并轻提示 【身份已确认】
状态机：
  • 状态集合：未绑定 / 待确认 / 已绑定 / 已失效
  • 未绑定 → 待确认：用户提交绑定申请
  • 待确认 → 已绑定：运营审核通过
  • 待确认 → 未绑定：运营审核驳回（可重复触发）
  • 已绑定 → 已失效：供应商解约或运营手动解绑
  • 已失效 → 未绑定：用户重新发起身份确认
  • 状态流转必须记录操作人与操作时间，驳回原因必填
功能名称　我的页面（身份区）菜单路径　小程序 / 我的接口地址　GET /api/wx/binding/current
数据源：
  • 微信昵称来自用户主动填写，非接口自动获取；填写后需点【保存】才入库（详见下方采集规则）
  • 供应商账号名称来自「供应商绑定关系」关联的「供应商档案」，本页只读展示
  • 绑定状态来自绑定关系记录，以状态标签形式展示
  • 绑定时间、绑定方式不在本页展示，仅供后台审核列表（5.6）与售后反查（5.7）使用
显示逻辑：
  • 身份区自上而下展示：圆形占位、供应商账号名称（主字，只读）、微信昵称（次字，行尾带 ✎ 图标）、绑定状态标签
  • 第一行为供应商账号名称，第二行为微信昵称，两行职责分离、不得合并
  • 昵称未填写时，第二行改为引导态 【微信昵称未设置，影响售后对接 · 点击完善 ✎】（橙色，整行可点）
  • 昵称完整展示，不做截断、不做省略；超出容器宽度时自动换行（长昵称占满多行也全部展示）
  • 圆形占位规则（两态），不得展示空白圆圈：
  • ① 昵称已填写 → 蓝底圆形 + 供应商账号名称首字（如「测试环境--井惠琳」取「测」）
  • ② 昵称为空 → 橙色虚线圆形 + 居中「待」字，与第二行的橙色引导态配套出现
  • 昵称换行时，末尾的 ✎ 图标对齐首行文字，不随文本下沉
  • 绑定状态标签配色与文案一一对应：待确认（橙）、已绑定（绿）、已失效（红）
  • 绑定供应商名称匹配不到时展示 【供应商信息异常，请联系运营】红字展示
  • 未绑定用户身份区展示 【未绑定供应商】，并提供【去绑定】入口
  • 身份区下方提供操作入口：【切换身份】（仅当该供应商名下存在多条绑定记录时展示）、【解绑】（已绑定态展示）
交互逻辑：
  • 点击昵称行末尾的 ✎ 图标：打开填写层进行更新
  • 填写层标题按状态区分：资料为空时显示【完善微信昵称】；已有值时显示【更新微信昵称】（v1.5 定稿）
  • 本页圆形占位与供应商账号名称行不响应点击，编辑入口仅 ✎ 图标一处，避免用户查看资料时误触编辑
  • 昵称为空时改由橙色提示行承担入口（整行可点），文案【微信昵称未设置，影响售后对接 · 点击完善 ✎】
  • 变更日志仅后台可查：C 端填写层与「我的」页均不展示日志入口，客服侧通过后台查阅历史昵称
  • 点击【切换身份】：仅当该供应商名下存在多条绑定记录时展示，点击后弹出身份选择列表
  • 切换后当前身份标识更新，主身份标记同步变更
  • 点击【解绑】：二次确认后提交解绑申请，提示 【解绑申请已提交，等待运营处理】
补充注意事项：
  • 昵称仅作展示与人工核对，绝不可作为绑定匹配的主键或唯一标识
  • 昵称允许用户修改为任意内容，需做特殊字符转义后再展示；展示侧不做长度截断（含 emoji、符号），按原文完整换行输出
  • 不做更新提醒：昵称变更不推送、不弹窗、不加过期标记，是否更新由用户自行决定；产品侧仅保证入口常驻可见
  • 供应商账号名称来自后台档案，本页只读展示，不提供修改入口；与微信昵称分两行呈现，职责分离
  • 客户端不得展示任何完整身份标识
功能名称　微信资料采集（昵称）菜单路径　我的页 / 昵称行 ✎ ；登录后落地页顶部引导条（仅资料为空时）接口地址　POST /api/wx/profile/nickname
数据源：
  • 昵称来源于用户在小程序内的主动填写，平台不提供接口自动读取
显示逻辑：
  • 填写层结构自上而下：标题、说明文案、昵称输入框（右侧「使用微信昵称」入口）、实时计数、用途提示框、【保存】按钮
  • 标题按状态区分：【完善微信昵称】（资料为空）/【更新微信昵称】（已有值）（v1.5 定稿）
  • 输入框下方固定展示引导文案 【点击键盘上方的「使用微信昵称」可一键填入】
  • 计数展示在输入框右下角，格式固定为 【当前字数/30】（如 0/30，不展示「剩余可输入字数」，两种口径不得混用）（v1.5 定稿）
  • 说明文案按状态两段：资料为空 → 【用于处理售后时，在售后群内找到你。微信不会自动提供昵称，需点「使用微信昵称」或手动填写】（v1.5 定稿）；已有值 → 【改了微信名，点一下重新获取再保存即可同步；进小程序不会自动更新】
  • 用户跳过未填写时，「我的」页昵称位展示引导态（见 5.4），不展示【微信用户】；仅在后台只读位置兜底展示【微信用户】
交互逻辑：
  • 获取昵称：点击输入框聚焦后，键盘上方出现「使用微信昵称」入口，用户点击才完成填充，也可直接手动输入
  • 未点【保存】就关层：昵称草稿保留，下次进入不丢失
  • 提交时机：仅点击【保存】按钮时提交；输入框失焦不自动提交（避免用户误触空白区域触发空值拦截）
  • 前置校验：
  • 昵称为空（含仅空格）→ 拦截提交，红字【请输入微信昵称】，输入框保持聚焦，不写库、不关层
  • 昵称与当前值相同 → 提示 【昵称没有变化】，不写变更日志，不关层
  • 昵称为必填项：空值一律拦截，不允许清空提交
  • 存储维度：昵称按「绑定关系」各账号独立存储（微信 × 供应商账号）
  • 包含表情、特殊符号时做转义后入库
  • 长度上限 30 个字符（按字符计数，emoji 计 1），达到上限后不再允许输入，计数变红提示，不做静默丢弃
  • 保存成功：提示 【保存成功】，关层并刷新「我的」页昵称与圆形占位；写一条变更日志（旧值 / 新值 / 时间，仅后台可查）；顶部昵称引导条同步消失
  • 填写层内点【取消】或点遮罩关闭：不写入，已填草稿保留在输入框，下次进入不丢失
状态机：
  • 状态集合：资料为空（昵称为空）/ 昵称已设置
  • 昵称为空 → 昵称已设置：保存成功的唯一出口；昵称一旦设置即进入「已设置」态
  • 昵称已设置 → 昵称已设置：更新为不同值，写新日志
  • 不存在「已设置 → 空」的流转：系统不提供清空昵称的操作，空值一律拦截
补充注意事项：
  • 研发硬约束（不可协商）：昵称输入框必须为可聚焦的 input type="nickname"，禁止设置 readonly 或 disabled —— readonly 输入框无法聚焦，将直接导致昵称填充能力失效
  • 回调返回的是临时文件路径，须立即上传至自有存储并落库；不得直接存储微信侧链接（会过期失效）
  • 「使用微信昵称」工具条由微信客户端在真机渲染，产品无法自定义样式、也无法程序化触发；基础库需 2.21.2 以上，开发者工具与模拟器不可见，验收必须在真机进行
  • 采集前必须在用户隐私保护指引中声明昵称的收集目的，未声明的采集会被平台拦截（运行时报错、无界面提示）；未声明即静默失效
  • 用户跳过采集是本场景的常态而非异常，所有下游展示都必须有兜底
  • 昵称的修改不影响已建立的绑定关系
  • 更新频率策略：不做任何系统侧提醒。不推送、不弹窗、不做“名称已过期”黄点或红点标记，更新完全由用户主动发起——用户自己改了微信名后，自行进入小程序点击更新入口完成同步
  • 唯一更新路径：我的页昵称行 ✎ → 填写层 → 点「使用微信昵称」→ 保存。缺「保存」则不入库，仅停留在输入框
  • 进入小程序不会自动同步昵称。小程序启动只做静默登录（换身份标识），微信不提供昵称读取接口、也不推送变更事件，因此“进小程序即自动更新”不具备技术可行性，需求与话术中均不得如此描述
  • 该能力的失败是静默的：未声明隐私指引、readonly 输入框、基础库版本不足，三种情况都不报错但都不生效，联调时必须逐项排查
  • 「昵称请与售后群昵称保持一致」的提示固定在填写层内（用途提示框），承担「为什么要一致」的解释；顶部引导条只保留一句提醒（文案见登录 PRD 功能块七 v1.5 定稿），不得把多句说明塞进引导条

六、绑定状态机

未绑定→ 用户提交申请 → 待确认→ 运营通过 → 已绑定→ 解约 / 手动解绑 → 已失效
状态触发条件可逆性异常兜底
未绑定无任何有效绑定记录—允许浏览，拦截业务动作
待确认用户提交绑定申请可被驳回，回退至未绑定，可重复触发超过 7 天未审核自动提醒运营，不自动通过
已绑定运营审核通过可被解绑，转为已失效—
已失效供应商解约、运营手动解绑、身份变更可重新发起确认，转为未绑定页面展示红字提示，引导重新确认
红线：任何状态下，系统不得依据昵称自动完成绑定。昵称只能产生「候选」，绑定必须经过用户点选 + 人工确认两道关卡。

场景系统处理用户感知

一个老板管理多家供应商允许多条绑定记录，主身份可切换我的页出现【切换身份】

八、埋点与度量

指标定义目标
自动绑定率进入小程序后无需任何确认即完成绑定的供应商占比尽可能高，体现主链路健康度
确认弹层转化率弹层出现后完成点选提交的比例用于评估候选质量与文案
一次通过率待确认记录中首次审核即通过的比例反映模糊匹配阈值是否合理
反查命中率客服发起反查并直接得到唯一结果的比例核心业务价值指标
昵称填充率绑定成功且已填写微信昵称的供应商占比决定售后 @ 人能否落地；因该能力依赖用户主动填写且平台无任何自动通道，需持续观测

关键埋点：登录识别结果分布、弹层曝光与点选、候选点击位置、搜索关键词、审核通过 / 驳回、反查关键词与结果数、昵称引导条曝光与点击、昵称填写层保存成功率。

九、验收标准

  • 已绑定的供应商再次进入小程序，无任何弹层与提示，直接进入首页
  • 未绑定的供应商首次进入，3 秒内看到身份确认弹层，且列表中存在正确候选
  • 弹层内不存在任何要求填写供应商实名的输入项
  • 未选中候选时主按钮置灰不可点，点击不产生任何提交；搜索无结果时展示引导文案且不产生提交
  • 提交绑定申请后，顶部出现待确认横条，业务动作被正确拦截
  • 运营驳回后，用户侧状态回到未绑定，可再次发起确认
  • 客服以微信昵称反查，能在一次搜索内定位到唯一供应商档案
  • 供应商修改微信昵称后，反查结果不发生变化
  • 任意页面、接口响应与客户端日志中均不出现完整身份标识
  • 网络异常、接口超时场景下，首屏仍可用，且给出明确的重试入口
  • 昵称为空时，「我的」页昵称行展示引导态（不展示【微信用户】），圆形占位转「待」态，顶部引导条出现
  • 昵称留空点击【保存】被拦截并提示，不写库、不关层；同名保存提示「昵称没有变化」且不写日志
  • 超长昵称（含 emoji）在「我的」页完整换行展示，不出现省略号、不溢出容器，✎ 图标对齐首行
  • 在真机上点击输入框时键盘上方出现「使用微信昵称」，点击后完成填入；「我的」页第一行供应商账号名称始终保持不变
  • C 端任何位置均不出现变更日志入口；后台可按供应商查阅昵称历史（旧值 / 新值 / 时间）
  • 圆形占位两态显示正确：① 昵称已填 → 蓝底账号名称首字；② 昵称为空 → 橙色虚线「待」。任何情况下不出现空白圆圈
  • 隐私指引中昵称已声明；移除后，该能力在真机上静默失效（用于回归自检）
  • 客服在售后反查详情中可查看该身份的昵称变更记录；用供应商改名前后的任意昵称检索，均能命中同一档案
  • 进入首页时若同时命中身份确认弹层与昵称引导条，只弹身份确认弹层；绑定完成或用户关闭后，昵称引导条才出现
